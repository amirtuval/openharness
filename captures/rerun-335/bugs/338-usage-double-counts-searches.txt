# Bug #338 — a provider-native search counted twice (found in the #314 re-run for #334/#335)

## Before the fix (commit cd8fbaa, the ask-first build of the branch)
A chat on openai/gpt-5-mini, one message asking for a fresh fact with web_search. The turn made
ONE model request that ran TWO provider searches:

  span.model_request_end.searches = 2
  two readable pairs: agent.tool_use{name:"web_search", source:"provider"} each answered by an
  agent.tool_result with its `sources`

but the usage answered:

  GET /v1/sessions/{id}/usage  -> "searches": 4
  GET /v1/me/usage?tz=UTC      -> "searches": 4
  the web header      -> "4 searches"
  oh's status line    -> "4 searches"

## After the fix (commit 26029f7)
The same case re-run against the fixed build: span.searches = 3, and

  GET /v1/sessions/{id}/usage  -> "searches": 3
  GET /v1/me/usage             -> "searches": 3
  the web header               -> "3 searches"   (capture t2-search-web.png)
  oh's status line             -> "2 searches"   (capture t2-search-cli.txt)

Fixes: `searchCounter` (apps/server/src/usage.ts) and `listToolUses` (both stores) leave a call
whose `source` is `provider` out — the request's own span already counted that search.
