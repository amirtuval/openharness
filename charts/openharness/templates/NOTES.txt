openharness {{ .Chart.Version }} is installed as release {{ .Release.Name }} in namespace

{{- if .Values.gateway.host }}
The app is served at https://{{ .Values.gateway.host }} — once its DNS record points at the
static IP {{ .Values.gateway.staticIpName | default "(GKE-allocated)" | quote }} and the
certificate map's certificate has issued. The load balancer is a GKE Gateway, not an Ingress:
watch for it with:

  kubectl describe gateway {{ include "openharness.fullname" . }} -n {{ .Release.Namespace }}
  kubectl describe httproute {{ include "openharness.fullname" . }} -n {{ .Release.Namespace }}

TLS comes from Certificate Manager (the `networking.gke.io/certmap` annotation on the Gateway,
`{{ .Values.gateway.certificateMapName | default "(none set)" }}`), and the certificate is
issued once its DNS authorization's CNAME record resolves:

  gcloud certificate-manager certificates describe <certificate> --project <project>
{{- else }}
No `gateway.host` was set, so no Gateway was rendered. Terraform sets it per environment.
{{- end }}

Check the rollout:

  kubectl rollout status deployment/{{ include "openharness.fullname" . }} -n {{ .Release.Namespace }}

The pods read /health for liveness and /ready for readiness; the load balancer's health check
is /ready (HealthCheckPolicy), so a pod whose database is down leaves the backend on its own.
