           OPENHARNESS_WEB_DIR=apps/web/dist, OPENHARNESS_ALLOW_PRIVATE_PROVIDER_URLS=1
  chat:    a local OpenAI-compatible stub (qa/chat-stub.mjs) registered as an
           `openai_compatible` credential named `stub`; it reports the prompt it was really
           sent at the brain's own chars/4 estimate, so the meter is a real measurement.
           GET /v1/models answers `stub/demo-chat` and `stub/demo-slow`, context_budget 32768.
  client:  `oh` built from this branch (apps/tui/dist), XDG_CONFIG_HOME isolated,
           attached with `oh -s <id>` to sessions driven through the API so the states are live.

Note — `oh` and terminal resize. The meter narrows correctly in a pane that is narrow when `oh`
starts (see §3, 50 and 40 columns). A terminal *resized while `oh` is running* does not reflow
the frame in this sandbox — the status line keeps the width it was last drawn at. That is not a
compaction-visibility regression and not `oh`'s code: a minimal Ink 7.1.1 app behaves the same
here (it renders `stdout.columns` once and never re-renders on resize, while Node's own
`process.stdout` 'resize' event fires and `process.stdout.columns` does update), so it is an
Ink/TTY interaction in this environment. The case as specified — a narrow pane — passes.
